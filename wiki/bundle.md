# Design bundle

Load this to change the bundle zip, its manifest or `context.md`, batch bundles, the font inventory or `figlens verify`. Emitted node fields and the `.fig` format are in `fig-format`.

## Bundle and batch mode (2026-10-22)

- Bundles include [preflight](mcp.md#shared-sources-and-runtime-behavior).
- `context.md` includes website-image handoff guidance. Inspect the target project's actual image components, neighboring pages, asset conventions and framework/loader/CDN configuration first; applicable instructions and docs supplement that evidence. Reuse its established delivery pipeline. With no established approach, keep bundle originals as sources, retain pure vectors as SVG, and prepare bitmap/mixed assets as WebP at display dimensions × DPR (PNG for lossless needs; evaluate AVIF when useful). SVG exports may embed full-resolution images, so inspect content and bytes before using them as web icons. When inlining or optimizing SVGs, keep the root `<g transform>` and unique definition ids (SVGO `prefixIds`, not `cleanupIds`; see `render`). Use `scale` to request resolution and `maxSize` to cap the longest side; `quality`/`maxKb` control lossy encoding, not dimensions. Export a selected node to preserve crops, masks and effects; without the source `.fig`, optimize bundle assets through project tooling. Create output directories and inspect MCP `isError`/`content` before retrying. Check returned sizes, responsive delivery, reserved layout space, main-image priority and offscreen lazy loading. Verify desktop/mobile transferred bytes and visual quality, measure LCP/CLS when possible, and report missing checks. PNG's MCP compatibility recommendation is for inline references, not a website delivery default.
- `figlens bundle <file.fig> <node> <out.zip> [--file-key K] [--name N] [--hash-source]` writes `manifest.json` (`format: "figlens-bundle"`, `version: 1`: producer, source file key, Figma URL and `source.sha256` with `--hash-source` (MCP `hashSource: true`; left out otherwise, since it costs a full read of the `.fig`: a 409 MB file took 0.15 s of a 1.15 s single-frame bundle, release build in Docker, 2026-11-02). It is the source `.fig`'s sha256 as bare hex; search refs' `snapshotId` is `sha256:` plus the same digest. CLI and MCP read the file's size and modification time before decoding and pass them to `bundle::write`; the digest is kept only if the file still has them before and after hashing, after the asset reads, so a save during decoding or bundling, or an unreadable file, makes it null. The last digest is cached by path and stamp in the process, so a batch or MCP server hashes a revision once while each separate CLI run hashes again. A same-size save that keeps the modification time is not detected, as in search's file-stamp freshness. The preview viewer's bundles do not record it), root paths, every file with role, media type, size and sha256), `design/nodes.json`, `design/variables.json`, `design/fonts.json`, `assets/` with `assets.json` and `missing-assets.json`, `references/screen.png` and `context.md` (how to build from the files). It prints `{nodeId, path, warnings}` on stdout: the warnings (missing assets and known render limitations; `missing-assets.json` contains only asset failures) go to stdout rather than stderr so MCP clients receive them. `export` likewise prints `{path, width, height, bytes, quality, layoutBox, renderBox, warnings}`; `tree` stays indented text (1.7x smaller than JSON on Nucleus UI at depth 3, 2026-10-29) unless `--json`. Over MCP, `bundle` and `export` declare an `outputSchema` and return that object as `structuredContent`. `--name` sets `root.name` (default the node's name); `--file-key` sets `source.fileKey` (default: taken from a Figma URL node argument).
- Frame lists: `tree --top-frames` writes one, for a file or `--frames -`; its screen rule is in the `discovery` topic.
- `figlens bundle <file.fig> --frames <list|-> --out-dir <dir> [--file-key K] [--jobs N]`: decodes once (`-` reads the list from stdin through the same `node_list` as `nodes` and `export`) and writes the bundle of each listed node id to `<dir>/<nodeId with : as ->.zip`, in parallel (default all cores), printing one JSON line per frame as it finishes: `{nodeId, path, warnings}` or `{nodeId, error}`. A frame's failure or panic is only its line; the exit status is nonzero only when the `.fig` or the list cannot be read. Bundles equal the single-frame command's except `createdAt` (72 of 72 zips checked). Historical timings are in [performance](performance.md#historical-batch-timings). `--jobs N` bounds concurrent frames (0 or omitted: all cores), not the rendering within each bundle. Frame workers and rayon use 8 MiB stacks; render assets and the reference rasterize in parallel and are added in plan order, so the zip is unchanged. `--jobs 1` runs frames sequentially while retaining inner rendering parallelism. Nucleus UI (172 frames, 12 cores): 35 s → 8.5 s with this and the filter-region fix; its largest frame 16391:2800 33.5 s → 5.9 s.

## Readiness check (2026-10-28)

A bundle proves its own integrity, not the project's readiness: it carries no font files, and only the running project can show whether faces load and assets deliver.

- `design/fonts.json` (`root.fonts` in the manifest, role `metadata`) lists `{faces: [{family, style, weight, postScriptName, nodeIds}]}`, one entry per family and style, from `bundle::fonts` over the emitted document. It covers visible text only (a hidden node skips its subtree), each node's own style when some character uses it (no overrides, override id 0, or fewer overrides than characters), and the `styleOverrideTable` entries that `characterStyleOverrides` actually applies, merged over the node style. Unused table entries are not faces.
- `figlens verify <bundle.zip|dir>` (MCP `verify` with `bundle`) reads a zip or its extracted directory and prints `{path, files: {verified, missing, changed, invalid}, missingAssets, fonts, fontLookup, unverified, findings, findingsSummary, truncated}`. Manifest and metadata lists are untrusted, so `files.missing`, `files.changed`, `files.invalid`, `missingAssets` and `fonts` each keep their leading entries within 256 KiB of serialized JSON; `truncated` maps each cut list to its original length (`{}` when none was cut), and `findingsSummary.scope` drops a root id or name over 1 KiB. Every manifest file is hashed against its size and sha256; `changed` carries expected and actual values; reading stops one byte past the declared size, so actual is null for a larger file, a directory or a link resolving outside the bundle. Manifest paths are untrusted: only plain relative paths are looked up, and other paths are listed under `invalid`. Files not in the manifest are ignored, so an agent may add its own. `missingAssets` repeats `missing-assets.json`. Fonts come from `design/nodes.json` through the same function, so bundles made before `design/fonts.json` existed also get an inventory; every face is `unverified` unless the local lookup below finds a file, and `unverified` names the browser checks left to the agent. JSON files over 256 MiB are refused. Each declared size is reserved from a 1 GiB hashing budget per bundle before reading, so total reads stay within it: a file whose declared size no longer fits is not read and is counted in `unverified`. An entry that cannot be read or decoded is listed as changed with `actual` null and its `error`; checking continues. A damaged `design/nodes.json` or `missing-assets.json`, already listed as changed, adds an `unverified` note instead of failing the report.
- `findings` is the handoff preflight (issue #57): `verify` already reads the bundle, which is scoped to one root node, so the report extends it instead of adding a command. Each entry is `{category, status, source, nodeIds, nodeCount, evidence, impact, action}`, built only from files the bundle already holds: manifest integrity (`integrity`), `missing-assets.json` (`asset`), `missingVariables` with the nodes whose fields alias each id plus one entry for resolved tokens still to match to the project (`variable`), a truncated `design/states.json` (`scope`), each node `_figlens.renderDiagnostics` (`render`) and `handoffDiagnostics` items (`semantics`), and font faces (`font`). `status` is `missing` (the input or its recorded content is unavailable, including a changed file), `unsupported` (known renderer or projection limit) or `unverified` (not established here: the project or browser must confirm it, or a figlens limit such as an invalid path, the hashing budget or a truncated inventory left it unchecked). `findingsSummary.semanticsCoverage` carries the handoff inventory's own `coverage` once (null over 1 KiB) rather than copying it into each semantic finding. Findings are ordered by status (missing, unsupported, unverified) before truncation; asset failures never mix with render or semantic limits. Design strings stay in `evidence`; `impact` and `action` are fixed text. Each `category/status` is counted in full but at most 500 of its findings are built, since the status sort and the cut never reach further and an untrusted bundle could otherwise multiply node ids and evidence; variable bindings hold references, not copies. `nodeIds` keeps 20 per entry and leaves out ids over 1 KiB and the list keeps 500 entries and 1 MiB of serialized findings, since evidence is copied from the untrusted bundle and MCP sends the report twice (structuredContent and escaped text, up to three times these bytes); `findingsSummary` keeps the scope, total, `unexamined` (metadata files that were absent or unreadable, so their findings are missing), per `category/status` counts, `truncated` and a coverage note that few findings prove neither readiness nor fidelity. Whether this helps an agent resolve a real handoff has not been measured.
- The report never blocks: exit status 0 unless the bundle or its manifest cannot be read, or the manifest is not `figlens-bundle` version 1. Under MCP `--root`, `bundle` is admitted and rechecked like other paths, and the reply keeps the caller's path.
- Local font lookup (`src/fonts.rs`, no dependency): `verify` (CLI `--fonts <dir>`, MCP `fonts`, admitted and rechecked under `--root` like `matchDir`) looks for each face in the project folder, then the platform's user and system font folders (macOS `~/Library/Fonts`, `/Library/Fonts`, `/System/Library/Fonts`; Linux `~/.local/share/fonts`, `~/.fonts`, `/usr/share/fonts`, `/usr/local/share/fonts`; Windows `%WINDIR%\Fonts`, `%LOCALAPPDATA%\Microsoft\Windows\Fonts`). A hand-written reader takes the sfnt `name` table of .ttf/.otf/.ttc (PostScript name, or family plus subfamily, ids 1/2 and 16/17; not OS/2 weight, so one variable-font file matches only its default subfamily); .woff/.woff2 match by file name alone (`matchedBy: filename`). A match makes the face `local_file` with up to 3 `localFiles` `{path, matchedBy, inProject}`; others stay `unverified`. A match inside `--fonts` also gets `fontFace`, an `@font-face` with `src` relative to that folder and `font-display: swap` (none for a collection); nothing is copied or downloaded, and licensing is the user's call. `local_file` is a name match, not browser readiness, and the `font/unverified` finding stays. Fonts are untrusted: 100,000 directory entries, 20,000 font files, 64 MiB read in total, depth 8, 256 tables, a 1 MiB name table, 4,096 records and 256-byte strings per font; every offset and length is checked against the file size and budget before the read, links to directories are not followed and a file link inside `--fonts` must resolve inside it, and `fontLookup` `{searched, filesRead, truncated}` says when a budget stopped the scan or a valid font was skipped for a per-font cap (an `unverified` face may then still have a file). Library `verify::verify` does no lookup.
- Not done here: lookup of fonts by weight alone or inside WOFF/WOFF2, and browser checks (asset URLs, decoding, rendered size, `document.fonts.load`), which need the running project. Agent guidance for those is in `skills/figlens/SKILL.md` and `context.md`.
