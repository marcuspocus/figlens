# Diff

`figlens diff <old.fig> <new.fig>` and MCP `diff` (`old`, `file`) compare one stored scope (`--node`/`node`, default `0:0`) of two saved revisions (#81). The engine is `src/search/diff.rs`; durable changes (#92) are to reuse it, not build another. Text output prints `no changes` only when no side stopped at a limit; otherwise `stopped early (<sides>)` with a `--node` hint (#162), as a whole-file diff of a large file used to say `no changes` above a `work_limit` coverage line.

## Build

Each side is a full relations build ([usages](usages.md)) through `build_with` with a facet collector, so ordinary search (text-only) and usages never pay for it. Per record it keeps, in `diff::FIELDS` order, each present effective field: the instance override (`Expanded.props`, or the expansion's size and matrix) else the stored field, the same rule as usages. A field's size is estimated first, walking no further than the side's remaining work (running out there stops the side, not just the field); past `VISITS` (65,536 visits) or an estimated 64 KiB (`FIELD_BYTES`; `derivedTextData` alone has a 4 MiB read cap, `DERIVED_TEXT_BYTES`, as glyph-rich data holds about 400 bytes a glyph, so a long text layer is read and `VISITS` still caps it near 10,000 glyphs; the side's 512 MiB, the prepaid conversion and unblob copies and the 512-byte field and 4 KiB record retained values are unchanged) it is `unread`, never converted or scanned again. Otherwise a stored value's conversion and a geometry or glyph field's unblobbed copy each pay the estimate first, and an expanded size or transform pays a fixed 512 bytes before it is built as JSON; it is converted to JSON (so a JSON override and the stored kiwi value digest alike) and streamed into SHA-256 over version, key, bytes and length, so escaping never buffers the whole value (a visit per started 64 bytes of the whole stream is charged before each chunk is hashed, as escapes can outgrow the estimate; a field may pay one unit more than a floor would), followed by the raw bytes only when JSON shows some as `<N bytes>` (an override that already holds such a placeholder is unread), so an override equal to the stored value digests alike. Geometry, vector and derived text fields (`fillGeometry`, `strokeGeometry`, `vectorData`, `derivedTextData`) digest the bytes of the blobs they name instead of the file-local blob index, keeping each index's place as `null` so an outline moved to another glyph still differs (`diff-v8`); `fontMetaData[].fontDigest`, the font file a layout was measured with, is left out (`UNCOMPARED`): no output reads it, and a re-derived instance holds it only as a placeholder, which would make every such text unread; a missing or malformed blob (`Tree::blob` reads compact bytes or an array of bytes), or one needing more than `VISITS` visits, makes the field unread; the value is kept only when it fits 512 bytes and the record's 4 KiB. A record with an unread field is listed with `unread`, never taken for unchanged, and counted in `unread_fields`: with no proven difference it is `unknown`, since a facet differs only when a field is present on one side alone or read on both with other digests, and with one it is `changed`; either way its `fields` list every field unread on either side (`{unread: true}` there), two unread digests never counting as equal; the kept unread entry is charged its metadata bytes as a read field's is. Every visit, byte and kept value is charged to the side's `Bounds` before it is kept. A side decodes, builds and drops its tree before the next side loads; only the two indexes with their facets stay.

Facets: `text` (textData, font fields, numeric font variants, leading trim, hyperlink, truncation, and `derivedTextData`, the laid-out lines and glyphs REST line heights and drawn text read), `layout` (size, transform, constraints, stack fields, clipping, layout grids), `appearance` (paints, stroke weights, effects, opacity, blend, a page's background, mask and mask type, visibility, radii, path geometry with the source sizes an expanded layer's outlines are scaled from, vector networks, and explicit variable modes, whose switch re-resolves the bound colors below without changing their cached paints), `properties` (component property definitions, assignments, refs, variant specs, a variable's or collection's own values, resolved type, collection, modes, scopes and code syntax, component, set and style descriptions and style type, Dev Mode annotations, a page's Ready for dev status map, the document's annotation categories, and prototype interactions, whose destinations are also edges), `structure` (name, type, parent, sibling order, hidden; from the record, and for the selected node its stored parent and position, which the index's root leaves out; it is charged to the side's bounds before the build, and when it cannot be verified the side is partial with `selection_context_unknown`) and `bindings` (the record's edges compared as relation, target, state and evidence, so a removed edge is listed; an `instance_of` change adds `swap` with both mains; a library style's edge targets its key, so a re-imported style with a new local id is no change). Outside the contract: library keys and versions (identity and publication, not values), a variable's `sortPosition` (order only), the `grid*` and `isSlotContent` keys `_figlens.unrepresented` lists by presence, and fills of sections above the selected node.

Stored generations (#92): `diff::tracked` is the one build both a live side and a tracked workspace build use. Its facets are stored per record as `fields` rows `[key, digest]` or `[key, digest, value]` and its `aliases` (`null` when unread, never read as none), and `facet_sets` holds the generation's facet layout (`facet_version()`, derived from `VERSION` and `FIELDS`) and selected-node context, `[origin, inherited]`: its parent and position, and how many ancestors above it set explicit variable modes. `revision` reads both stored generations back through `store` and compares them with the same `compare`, so the reply equals a live diff of the same trees; `revision_live`, which an index worker runs at the end of `write`, takes the new side from the build that saved it, with the same result, and the worker reports it within `WORKER_OUTPUT` (8 MiB, else omitted) so its owner, which uses it only while the tracking epoch and the job's expected generation are still the ones compared, never reads both generations back; each read pays the live `BYTES` as the live build does, the row text before parsing and then each kept field's metadata (`FIELD_META`), key and value at its held JSON size and each alias id as the live build charges it, and refuses more rows than the generation has records. A missing, tampered or other-layout facet set is `index_incompatible`, never compared.

Impact (#92): `diff::revision` also runs `impact::compute` over the two indexes its pair already holds, seeded by its kept rows (`UNREAD` stripped; retyped and unknown rows seed as unknown) and, for a removed or added subtree kept as one row, each layer below its top that the other side lacks, with the top's change, with its own bounds sized as the pair's, which pay each seed's copy first (a kept row whose seed does not fit stays a row but counts as `seeds_truncated`). `PairEvidence` answers each probe with `proof`, the per-facet test `differs` uses: `changed` only for a proven difference, `equal` only when the facet has a field and every field is read on both sides; one facet bit per probe. A probe reads only the reached record's own fields, so `effective_unchanged` says that layer's facet is equal, never that its subtree or render is: an instance's expanded children (`I<instance>;<child>`) carry their own change rows. Structure is proven only on sides that did not stop, expanded every hidden layer and know the root's origin. A record one side lacks, a retyped record, edges, unread or several bits are `unknown`. A layer binds a variable as `VariableID:<id>` while the diff seeds its raw id, so a variable's step also follows that id; the bound layer's own fields hold only the binding, and the variable's facet is not the field's, so it is never asked: it and what it reaches stay `possible` (`comparison_unknown`). No index edge records a variable's aliases or collection, so `PairEvidence::aliasing` answers from the variables' captured `aliases`, one reverse map per side built and paid once: a variable reaches those aliasing it (`via` `binds_variable`) and a collection its variables (`via` null), each `possible`, link by link through cycles; a side that stopped, hid layers or left a variable's targets unread is `relation_unverified`. The id maps and orders it keeps are paid first, each lookup's fields before reading them. The walk's `complete` also needs the comparison's coverage (else `source_comparison_partial`) and every change kept as a seed (else `seeds_truncated` with the omitted count), so an incomplete pair never reads as a complete empty impact. `place` then gives each hit its top-level frame on each side it is on, from the probes' id maps (paid first when absent), else `frames_unknown`. A tracked publication records it with the revision ([changes](changes.md)).

## Matching and coverage

Records match by exact id within the selected pair, and the reply says `matching: {basis: node_id+kind, lineage: unverified}`: two caller-chosen files are never proven to be one Figma file. Same id with another type is `kind_changed` with `identity_uncertain`. A record missing on a side that stopped (`stop` set), or below a layer that side hides and left unexpanded (`hidden_content`), is `unknown`, never removed or added; so is a matched record whose only difference is an unread field. Hidden layers either side left unexpanded (`hidden_content_not_expanded`) and links its index could not verify or read (`relation_unverified`) may hide changes, so each is a per-side coverage reason with its count and that side is not complete. So is a style, variable, main component or component set an in-scope layer uses whose definition is not a compared record (`definition_not_compared`): its values, or the property definitions and defaults a main declares or a variant inherits from its set, which name the emitted properties, can change while every compared record stays the same, and the diff does not follow it (a definition inside the scope is compared as its own record). A compared variable's aliases count too: while its `variableDataValues` is digested, the variable each mode aliases is captured, one per aliasing mode as edges count uses (a visit per entry, then the id's length measured on the borrowed reference and charged twice, for a local guid's own string and the formatting buffer, before its one copy is made), and each that is not a compared record is one such use, since REST resolution follows an alias across pages into bound fills; a chain is checked link by link, as each in-scope variable reports its own targets, so A→B→C with only C outside is partial while a chain kept within the compared records is not. A variable whose values were unread counts as one, its targets unknown (`diff-v9`). Its collection counts the same way (`variableSetID`, captured with the aliases as its library key or guid, as `rest` matches it): REST resolves a binding in the collection's first mode by sort position unless a layer sets one, so reordering an outside collection's modes changes resolved fills while every compared record stays the same; an unread `variableSetID` counts as one. So does each ancestor above the selected node that sets explicit variable modes (`variableModeBySetMap`), which REST inherits into the selection (`rest::context`) and applies when it resolves the bound colors of instance copies again, while no compared record holds it (counted whether or not the scope binds that collection); that walk is charged per step and bounded by `DEPTH`, and a chain it cannot finish counts one more (`diff-v10`, which also rebuilds stored generations saved before collections were captured). `diff-v11`: an expanded record's fields read a K-scaled instance's lengths at its factor and take every derived field (see [instances](instances.md)), so facets stored before are another version. Dev Mode state above the scope counts the same way (`outside_dev_mode`): one for a page's Ready for dev map holding a compared record, one for the document's annotation categories when a compared annotation names one; at the page or document they are compared fields (`handoffStatusMap`, `annotationCategories`). The gap follows whether the target is absent from the compared records: a library main whose cached copy is among them is compared as saved content, without proving the library is current, while a library style or variable reference (a key, never a record id) or a reference to a record present in the file but outside the compared ones leaves even a whole-file diff partial. An added or removed subtree is reported at its top record with `descendants`, except that the selected node's children are always listed, so `--node` drills into one. A selected node present on one side only leaves the other side empty and complete (`coverage.<side>.selected: false`); on neither side it is `node_not_found`. Removed and added top-level frames of one page that share a name, else the same rounded size and position, get a labelled `possibleMatch` (at most 200; each candidate is probed once and charged, and lookup keys are charged before they are copied); they stay removed and added.

## Paging and cache

Changes are kept once per pair as a compact list (frame, record indexes, facet bits). The id maps and sibling orders of both sides, every compared record's fields and edges, each change, frame and subtree entry are charged to a pair budget (`PAIR_WORK`, `PAIR_BYTES`) before the work; past it the reply is partial with `diff_work_limit`. Pages slice that list in frame order (100, 1-500), and each frame's summary counts the whole list (`N listed`, every kind, then per facet and unread), so a frame split across pages still reports its full count. A page spends at most 256 KiB (`PAGE_VALUES`) on names, frame headers (strings counted at their escaped JSON length, as control characters grow sixfold), listed fields' keys and markers (charged per change before its edges, so edges never crowd them out), a swap's ids (marked `truncated` when they do not fit), field values and edge entries, a payload budget rather than a cap on the serialized reply (the MCP 8 MiB reply cap bounds that): a value over it says `truncated`, edges over it are counted in `edges.truncated`, and once a page is full it ends early with `nextCursor` at the next change, so none is dropped; a first change that alone passes it is `response_budget`. Edge comparison costs one of `PAGE_WORK` visits per edge, checked with an estimated 64 set bytes per edge (`EDGE_SET_BYTES`, accounting only, not a measured heap cap) before the sets are built: a changed record whose edges do not fit ends the page before it, or is `query_work_limit` (with a `usages --out` next step) when it comes first. Edge differences are a set difference of both sides' edges, and the unread count is kept with the pair, so a cached page costs its listed changes plus their edge visits, not a scan of the pair. The cursor binds the version, both sourceIds, snapshots and built signatures (generation and stop), the node and a digest of the retained ordered result (changes, frames, counts and the pair's stop, hashed once when the pair is built, a visit per change and frame paid as each is kept, so a page reads it without rehashing), so a rebuild over the same sides that stopped elsewhere is `cursor_stale` too; another pair is `cursor_stale`.

The process keeps one pair (`PAIR`), replaced when a call names other paths, stamps or node, rechecked against both stamps on every page and rehashed after `REHASH`; a deadline-stopped side is never cached. MCP pages reuse it; each CLI call is a new process, so a CLI cursor rebuilds both sides. MCP admits `old` like `file` (checked against `--root` on admission and every page); `gs://` sources are refused.
