# Browser pull

Load this for selection, browser profiles, login/logout, the helper protocol and installation. For shared browser/API account routing and environment-reference setup, load [accounts](accounts.md). For metadata comparison, load [freshness](freshness.md).

`figlens pull` (#225, CLI only: it can open a login window and wait minutes, which suits no MCP call) refreshes mapped copies. Code: `src/command/pull.rs` (selection, lock, validation, replace) and `npm/pull/helper.mjs` (the browser).

- Selection: with neither `--only` nor `--stale`, nothing is downloaded and the `freshness` listing prints with a `hint` (#225: list, do not download everything). `--only NAME` (repeatable; an unknown name fails before the browser), or `--stale`, which runs the freshness check and pulls only `stale` copies and missing files (using each design's effective API account); others are `skipped` with `current` or the unknown reason. Before the browser, each selected entry must have a URL figlens can key, a name no other selected entry uses (downloads come back by name) and a `file` of plain relative parts (no `..` or absolute path, so a cloned mapping cannot aim a pull outside its project); unselected entries are not checked. `--login` reads no mapping. `--logout` reads none either and starts no helper: under the lock it deletes every legacy and named browser profile and prints `{logout, removed}`; its only permitted companion is `--account NAME`, which deletes just that account and includes `account` in the report.
- Accounts (#241): `--account NAME` overrides each selected entry's `account`; with neither, the legacy default stays at its original paths with all cookies (no migration or forced sign-in). `--login --account work` signs into that alias without a mapping. Mixed selections group by effective account in first-appearance order, then invoke the helper once per group sequentially; one group's profile/export/helper failure preserves its failed targets and does not block later groups. Never retry a denied design under another account. An alias labels a browser profile, not a verified Figma identity: the user chooses the identity in the login window.
- State lives in per-user `pull/` (0700): `lock` (an OS file lock, released on process exit), legacy `profile` (playwright-core) and `agent-browser-profile`, named `accounts/account-<alias>/` containing the same two browser folders, and `downloads` (cleared under the lock at start and end). Profiles are 0700 and shared across projects of this user; browsers stay separate because their Chrome builds may not read each other's cookies. The `account-` prefix avoids reserved directory names on Windows. Profile directories cannot be symlinks; validate `accounts/` before traversing it, including logout.
- Browser login and API tokens are independent. The same effective alias resolves an environment reference in the global accounts registry; see [accounts](accounts.md). `--stale` skips unknown existing copies (including missing configuration/token or 401/403), while missing files remain eligible. When every selected entry is unnamed, a missing default `FIGMA_TOKEN` still fails before selection, preserving the old behavior. Mixed or named selections report individual failures as skips. `--only NAME` needs no API token.
- Helper contract: figlens runs `FIGLENS_PULL_HELPER` (`node` for `.mjs`/`.js`; the npm launcher sets it to its `pull/helper.mjs`), writes one JSON line `{profiles: {playwright, agent-browser}, browser, downloads, login, designs: [{name, url}]}` (`browser` is `--browser`, or null) with key-only `https://www.figma.com/design/<key>/` URLs, and reads one stdout line per design, `{name, path}` or `{name, stage, error}` (`open`, `editor`, `menu`, `export`, `download`). stdin stays open until stdout ends, and the helper exits when it closes, so a killed figlens leaves no Chrome on the profile; figlens kills the helper on its own errors. stderr is relayed as progress, and its last line is the reason for designs the helper never reached. Retain completed install results on stream/wait errors; only unfinished designs fail.
- Install: the path must be inside `downloads`; the file must open and decode (`Document::open` and `take_message`), carry `exported_at`, and not be older than the current copy's; then `output::write` replaces it (an exclusive sibling renamed over it, keeping the target's permissions and symlink); install failures have stage `install`. Any failed check leaves the target as it was. No backup is kept.
- Report `{mapping, designs: [{name, file, state: pulled|skipped|failed, savedAt, reason}]}` on stdout in selection order; named selected designs add `account` (including skips/failures), while default designs keep the old shape. Named login/logout also add `account`; the command fails when any design failed, after printing it.
- Browser: `--browser playwright|agent-browser`, else `playwright-core` when the helper finds it, else `agent-browser` on PATH; with neither, the error names both installs. Both run the same flow below behind one page interface in `helper.mjs`.
- The helper finds `playwright-core` beside itself (a global install) or in the working directory's project, launches the installed Chrome (`channel: 'chrome'`) with the profile, sends the regular Chrome user agent in both modes, and on an expired session relaunches headed at `/login` and waits up to 10 minutes for `/files/`. Per design: open the key-only URL (a percent-encoded name slug made CloudFront answer 403), wait for `Main menu`, then File > Save local copy (English UI only; refused when disabled), and take Playwright's download event within 10 minutes. It stops at the first failure within its account group.
- `agent-browser` (checked on 0.38.1) runs the same steps as CLI calls in the fixed session `figlens-pull` (the lock allows one pull), closed on exit and on SIGINT, SIGTERM and SIGHUP; one left by a SIGKILL is closed by the next launch, with `--profile`, `--download-path downloads/agent-browser`, `--headed`, `--user-agent` (Chrome, not HeadlessChrome) and `--idle-timeout 10m` as launch flags; launch flags apply only when the session's browser starts, so each launch closes the session first. Waits poll `eval` (a failed poll, as during a navigation, keeps waiting), since `wait` takes no timeout for selectors, with `AGENT_BROWSER_DEFAULT_TIMEOUT` raised to the 120 s editor wait for heavy navigations. The download is not taken from `download` or `wait --download`: one CLI call gave up after about 150 s waiting on its daemon, under a Figma export's minutes. Instead the click lands in the session's download folder, done when its one file has no `.crdownload` suffix (Chrome's partial name) and the same size on two polls, then it is renamed to `downloads/<index>-<name>`. Export progress checks run one at a time, each after the last returns. Known gaps: a download Chrome abandons shows as `export` after the 10 minute wait rather than `download`; the user's agent-browser config and `AGENT_BROWSER_*` environment still apply (a `cdp` or `allowedDomains` setting breaks the profile launch); Windows npm `.cmd` shims are not found, since the helper spawns `agent-browser` without a shell.
- Ported from a project script that ran this flow with `agent-browser` (2026-11-04 handoff). Not exercised against Figma in CI: `tests/freshness.rs` drives the CLI with a shell helper stand-in, and `npm/pull-helper.test.mjs` checks the messages with neither browser and with `agent-browser` missing, and runs the agent-browser flow against a stand-in CLI, including the session closing on SIGINT. Signing in from the automated profile was reported to sign the person out of Figma elsewhere (unconfirmed); `--help`, the docs table and the skill say so.
- Pi, OpenCode, OMP and Herdr: no tool or adapter; named browser accounts remain CLI-only, and MCP freshness uses the same account registry and adds an optional `account` override; adapters discover it through the shared contract. The skill's `Refreshing a saved copy` section (served by `workflow` build, audit and yolo; the MCP instructions point at pull) tells the agent when to pull, to ask first, to leave the sign-in to the person, and what each failure `stage` calls for.
